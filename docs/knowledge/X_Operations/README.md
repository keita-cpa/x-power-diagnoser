## rules/ — 自動投稿システムが守るべき運用ルール

| ファイル | 本プロジェクトへの要点 |
|---|---|
| X自動化開発ルール | **auto-poster の生命線**。許容: 自前コンテンツの自動投稿。禁止: 複数アカウント同時投稿・重複ポスト・無差別フォロー・スパムDM。リプライ自動化は「相手との過去交流」が条件 → sniper_radar は起案のみ・送信は人間判断を維持すること |
| X検索ルール | 重複ポスト・ハッシュタグ乱用・過度なフォロー解除で検索除外。検索除外されてもフォロワーには表示される（気づきにくい）→ IMP急減時はまずこれを疑う |
| Xアカウント警告と凍結 | 警告→検索除外→一時停止→永久凍結のエスカレーション。異議申し立て可。凍結はアカウント資産の全損 → グレー運用は絶対にしない |
| Xルール概要 | 3層構造: 安全性 / プライバシー / 信頼性。違反リスク評価のフレームワーク |
| X信頼性ポリシー | 偽装アカウント・エンゲージメント不正（いいね自動化等）の禁止。**ペルソナ運用は「架空の人格」ではなく「本人の一側面」として運用すること**（なりすましとの境界) |
| X個人情報ポリシー | 本人の同意なき個人情報（所在地・連絡先等）の共有＝晒し行為の禁止。**紹介ポスト・リプライで他者アカウントに言及する際の境界線の根拠**。守秘フィクション化（persona.md）のプラットフォーム側の裏付け |
| XAPIガイド | APIの5分類（アカウント/ポスト/DM/広告/SDK）と権限モデル（初期設定はアクセス許可なし・アプリ単位で許可）。**OAuth 2.0移行（MASTER_ARCHITECTURE §8）の基礎資料** |
