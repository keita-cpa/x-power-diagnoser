### 2-3. スコアリング：WeightedScorer の22シグナル [C]

`ranking_scorer.rs` の `ScoringWeights` 構造体から確認済み:

**ポジティブシグナル（重みは正）:**
| シグナル | 意味 |
|---|---|
| `favorite` | いいね |
| `reply` | リプライ |
| `retweet` | リツイート |
| `photo_expand` | 画像展開 |
| `click` | クリック（詳細表示） |
| `profile_click` | プロフィール訪問 |
| `vqv` | ビデオ視聴（min_video_duration_msを超えた場合のみ） |
| `share` / `share_via_dm` / `share_via_copy_link` | 各種シェア |
| `dwell` | 15秒以上の閲覧 |
| `quote` / `quoted_click` / `quoted_vqv` | 引用関連 |
| `follow_author` | 著者フォロー |

**ネガティブシグナル（重みは負）:**
| シグナル | 意味 | 旧twitter/the-algorithm比較 |
|---|---|---|
| `not_interested` | 「興味なし」 | — |
| `block_author` | ブロック | −74倍相当 [K] |
| `mute_author` | ミュート | −31倍相当 [K] |
| `report` | 通報 | −369倍相当 [K] |
| `not_dwelled` | 非閲覧（スクロールスルー） | — |

**最終スコア計算式** [C][A]:
```
Final Score = Σ (weight_i × P(action_i))
```
- 正のアクションは正の重み付け
- 負のアクション（ブロック・ミュート・通報・興味なし）は負の重み付け（スコア引き下げ）
- **具体的な数値はコードに記載なし** → `xai_feature_switches::Params`（動的フィーチャースイッチ）で管理

> **2026年の重要変更点**: 旧システムは重みをScalaコード内にハードコードしていた。新システムは`xai_feature_switches::Params`による動的管理のため、Xは重みをいつでもコード変更なしで調整できる。

### 2-4. Author Diversity Decay [C][G]

`ranking_scorer.rs` と `author_diversity_scorer.rs` で確認された計算式:

```
multiplier(position) = (1.0 - floor) × decay_factor^position + floor
```

| パラメータ | 説明 | 旧システム値 [B] |
|---|---|---|
| `floor` | スコア下限（最小乗数） | 0.25 |
| `decay_factor` | 減衰係数 | 0.5 |
| `position` | 同著者内での出現順序（0始まり） | — |

旧システムでの実例（position=0〜3の場合）:
| 連続出現 | 乗数 |
|---|---|
| 1件目（position=0） | 100.0% |
| 2件目（position=1） | 62.5% |
| 3件目（position=2） | 43.8% |
| 4件目（position=3） | 34.4% |

### 2-5. Out-of-Network（OON）調整 [C][D]

`ranking_scorer.rs` で確認されたOON処理の種別:

| 条件 | 適用される重み係数 |
|---|---|
| トピック検索時 | `TopicOonWeightFactor`（専用値） |
| 新規ユーザー（フォロー数がNEW_USER_MIN_FOLLOWINGを超えていない） | `NEW_USER_OON_WEIGHT_FACTOR`（新規向け緩和値） |

**旧システムからの確認値** [D]: `OONTweetScalingScorer.scala`より **ScaleFactor = 0.75**（コードから直接確認）

### 2-6. フィルタリング [H]

**Pre-Score フィルタ（スコアリング前）**:
- `drop_duplicates_filter.rs`: 重複排除
- `age_filter.rs`: 古すぎる投稿を除外
- `self_tweet_filter.rs`: 自分の投稿を除外
- `author_socialgraph_filter.rs`: ブロック・ミュートユーザーを除外
- `muted_keyword_filter.rs`: ミュートキーワードを含む投稿を除外
- `previously_served_posts_filter.rs`: 直近提供済み投稿を除外
- `ineligible_subscription_filter.rs`: サブスクリプション条件チェック

**Post-Selection フィルタ（選択後）**[H]:
`vf_filter.rs`（Visibility Filter）で確認された除外対象:
- `SafetyCheck = Drop` と判定された投稿（安全性違反）
- スパムとして検出された投稿
- ポリシー違反フラグ付き投稿
- 削除済み投稿（`FilteredReason` がある投稿はほぼ全除外）
- **保持**: `FilteredReason = None`（理由なし）の投稿のみ通過

### 3-1. FeedbackFatigue パラメータ [E][F]

`FeedbackFatigueScorer.scala` から直接取得:

| パラメータ | 確認値 | 意味 |
|---|---|---|
| `DurationForDiscounting` | **140日** | フィードバック割引の対象期間 |
| `ScoreMultiplierLowerBound` | **0.2** | スコア乗数の最小値（20%まで低下） |
| `ScoreMultiplierUpperBound` | **1.0** | スコア乗数の最大値（100%） |
| `ScoreMultiplierIncrementsCount` | **4段階** | 割引レベルの段階数 |
| `ScoreMultiplierIncrement` | **0.2** | 段階ごとの乗数増分 |
| `ScoreMultiplierIncrementDurationInDays` | **35日** | 段階ごとの時間間隔（35日×4=140日） |

`HomeGlobalParams.scala` から直接取得:

| パラメータ | 確認値 | 意味 |
|---|---|---|
| `FeedbackFatigueFilteringDurationParam` | **14日** | 完全BAN期間（FeedbackFatigueFilter） |

**仕組みのまとめ**:
- 「興味なし」を押すと、対象アカウントの投稿スコアが段階的に低下
- 0〜35日: 乗数0.4（60%削減）
- 35〜70日: 乗数0.6（40%削減）
- 70〜105日: 乗数0.8（20%削減）
- 105〜140日: 乗数1.0（元に戻る）
- かつ最初の14日間は完全BAN（`FeedbackFatigueFilter`）

## 4. X公式ルール（help.x.com から直接取得）[I][I2][I3][I4][I5]

### 4-1. Xルール 3大カテゴリ [I]

**安全性**:
- 暴力的な発言・脅迫・暴力の煽動・賛美の禁止
- 暴力行為・ヘイト行為団体への参加・奨励の禁止
- CSAM（児童性的搾取）: 一切容認しない（即時永久凍結）
- 嫌がらせ・特定人物への攻撃的コンテンツの禁止
- 人種・民族・性別・性的指向・宗教・障碍等によるヘイト行為の禁止
- テロリスト・暴力的過激派アカウントの削除
- 自殺・自傷行為の助長・推奨の禁止
- センシティブメディア（グロテスク・暴力・成人向け）のプロフィール画像等への使用禁止

**プライバシー**:
- 個人情報の無許可公開の禁止（ドクシング）
- 合意のない裸体の描写の共有禁止
- アカウントの乗っ取り禁止

**信頼性**:
- プラットフォーム操作・スパム（→詳細: 4-2）
- 市民活動の阻害（選挙操作・誤った投票日時情報等）の禁止
- なりすまし・偽のアイデンティティの禁止
- 合成・操作されたメディアの共有禁止
- 著作権・商標の侵害禁止
- 動画コンテンツ内の無許可サードパーティ広告禁止

### 4-2. プラットフォーム操作・信頼性ポリシー（2025年4月版）[I2]

**偽アカウントとして禁止される行為**:
- **許可されていない自動化**: Xの開発者ポリシーに準拠しない自動化・スクリプト化されたアカウント
  - 最終的な責任は利用者本人が負う（サードパーティアプリ経由でも同様）
- **架空のペルソナ**: ストック画像・盗まれた画像・AI生成プロフィール画像を使った欺瞞的な身元情報
- **なりすまし**: 他の個人・グループ・組織のアイデンティティを偽装すること
  - パロディ（PCF: Parody/Commentary/Fan）アカウントは情報・風刺・ファン目的のみ許可
- **複数アカウント・共謀**: 共謀による偽装行為で会話を人為的に操作すること
- **禁止措置の回避**: Xの強制的措置を回避すること
- **アカウントの乗っ取り**: 無許可でのアクセス・変更

**偽装行為として禁止される行為**:
- **コンテンツスパム**: Xの利用者体験を損なう形での大量・重複・無関係コンテンツの共有
- **エンゲージメントスパム**: エンゲージメント機能を不正使用してトラフィックを人為的に操作
- **詐欺**: 金銭・財産・個人情報取得を目的とした詐欺行為

**偽装コンテンツとして禁止される行為**:
- 公共に混乱をもたらす合成・操作されたメディアの共有
- マルウェア・フィッシング・詐欺目的の悪意のあるリンクの共有

## 5. 凍結の理由・種類・解除手順（公式ページより）[I3][I4]

### 5-1. 凍結の3大理由 [I3]

公式ページに記載されている凍結理由:

1. **スパム行為**: アカウントが凍結される原因の「ほとんど」がスパム行為または明らかな偽装
   - スパムアカウントはXや全ユーザーのセキュリティリスクと判断される
   - 本人の正規アカウントでも「手違いで凍結されることもまれにある」と明記

2. **セキュリティが危険な状態にあるアカウント**: 乗っ取り・ハッキングの疑いがある場合
   - アカウントのセキュリティが確保されて所有者の管理下に戻るまで一時凍結

3. **攻撃的なポストや行動**: 嫌がらせルールに抵触という報告があった場合
   - 脅迫・なりすましなどの嫌がらせに関与したアカウント → 一時または恒久凍結

### 5-2. Xの対応の段階的プロセス [I4]

公式「対応についての理念」から（2025年版）:

**判断に使われる5つの要素**:
1. 個人・グループ・法的に守られるべきカテゴリへの攻撃かどうか
2. 攻撃的行為の対象者本人が報告したか、第三者が報告したか
3. 違反者にXポリシーの**違反歴**があるかどうか
4. 違反の**重大さ**（物理的・感情的・金銭的な被害）
5. コンテンツが**公共の利益**にかなっているかどうか

**段階的な対応フロー** [I4]:
```
初回違反（故意でないと仮定）
  → 違反ポストを見せて説明
  → 削除しないと新規ポストできないと通知

繰り返し違反
  → 違反ポスト削除要請
  → アカウント所有権認証要求
  → 一定期間の投稿制限

さらなる違反
  → 永久凍結
```

**即時永久凍結（重大違反）**:
- 強烈な身体的脅迫コンテンツ
- 同意を得ていない私的画像・動画
- CSAM（児童の性的搾取コンテンツ）

**ニュース性・公共の利益がある場合**: ルール違反でも残される場合あり（ケースバイケース判断）

### 5-3. 凍結の種別と解除手順 [I3]

| ログイン時の表示 | 種別 | 解除方法 |
|---|---|---|
| 電話番号入力・メールアドレス確認を求められる | ソフトロック | 画面の指示に従って認証 |
| 「アカウントがロックされた」メッセージ | 機能制限 | ロック解除手順に従う |
| 自分で解除できない | ハード凍結 | 異議申し立て |

**ソフトロック解除**（公式手順）:
1. ログインして画面の指示に従う
2. 電話番号入力またはメールアドレス確認
3. 一定期間ポストできない場合あり

**異議申し立て**（公式手順）:
1. 凍結されているアカウントにログイン
2. ブラウザで新しいタブを開く
3. 異議申し立ての詳細を入力して送信
4. 手違いの凍結と考えられる場合に利用可能

**凍結されたアカウントの停止（アカウント削除）**:
- 先に異議申し立てが必要
- 異議申し立て後なら削除リクエスト送信可能

**個人情報の取り出し**:
- 凍結中でも個人情報へのアクセスリクエスト可能

### 5-4. 予防設計（凍結を回避するための実装状況）

| 施策 | 公式根拠 | @Keita_CPAでの実装状況 |

## 6. X記事（Article）のアルゴリズム・ルール

### 6-1. X記事とは

X Premium限定の長文記事機能（2023年8月導入）。タイムライン上でカード表示され、クリックすると記事ページへ遷移する。

### 6-2. アルゴリズム特性（コードから類推）[C][A]

| 通常投稿（280字） | X記事 |
|---|---|
| タイムライン上での全文表示 | カード（タイトル＋画像＋冒頭130字）表示 |
| Show More = タップ → ×20ブースト [K] | カードタップ = Show Moreと同等以上の強シグナル |
| `dwell`（15秒以上閲覧）が加算 | 記事閲覧時間 = 長時間dwell として機能 |
| `follow_author` 誘発 | 記事品質が高いと `follow_author` 誘発しやすい |
| 外部リンク = −50%ペナルティ | 記事URL自体は問題なし（記事本文内URLは注意） |

**記事カード設計の重要ポイント**:
- タイムライン表示では**タイトル＋画像＋冒頭約130字**のカードのみ見える
- 130字で答えを出し切らない「余韻型」設計でタップ率を最大化
- タップ = 強いシグナル → 配信拡大

### 6-3. フォーマットルール

| 項目 | 通常投稿 | X記事 |
|---|---|---|
| Markdown見出し・太字 | **禁止**（生テキスト表示） | **使用可**（記事エディタがレンダリング） |
| 箇条書き | 禁止 | 使用可 |
| 絵文字 | 禁止 | 禁止（cp932・世界観維持） |
| 本文内URL | 禁止（-50%ペナルティ） | 原則禁止（note導線フェーズで再検討） |
| API経由の自動投稿 | 可能 | **不可（手動入稿のみ）** |
| 文字数 | 280字 | 無制限（目安3,000〜4,500字） |

### 6-4. 公開後の運用（アルゴリズム最大化）

1. 公開数時間前に予告ポスト（期待感の醸成 → 初速30分に貢献）
2. 公開後24〜72時間はプロフィールにピン留め（発見性のゴールデンタイム）
3. 重要な抜粋を通常ポストとして投稿し記事リンクを添える
4. 早期リプライに積極的に返信（著者→リプライ返信+75 [K] を発動させる）
5. エバーグリーン記事は関連話題が再燃したタイミングで再共有

## 7. 伸びているアカウントの発見・分析・活用

### 7-1. 発見方法

**方法A: X検索の高度活用**
```
# ニッチ内の高エンゲージ投稿を探す
[キーワード] min_faves:50 min_retweets:10 lang:ja

# 記事機能で伸びているアカウントを探す
[キーワード] filter:articles min_faves:20 since:2026-01-01
```

**方法B: 大アカウントのリプライ欄逆引き**
- フォロワー1万以上のアカウントの投稿リプライ欄を確認
- 高いいいねを得ているリプライをしているアカウント = 成長途中

**方法C: sniper_radar.py の target_accounts.txt に登録して継続監視**
- 発見した成長アカウントを `data/config/target_accounts.txt` に追加
- 投稿パターンを継続的に監視し、`/project:buzz-variants` に活かす

### 7-2. AlgoScore試算による分析

観察対象の投稿に簡易スコアを試算:
```
AlgoScore = (著者→リプライ返信×75) + Reply×13.5 + Bookmark×10 + RT×1 + Like×0.5
```

例: いいね50・RT5・リプライ10・ブックマーク8・著者リプライ返信3件
→ `(3×75)+(10×13.5)+(8×10)+(5×1)+(50×0.5)` = **470点**

高スコアアカウントの投稿を `gem_analytics_scientist.md` に貼り付けて `prompts.py` 改善案を抽出する。

### 7-3. コバンザメ戦略（実証済み最高効率）[K]

- リプライのIMP平均 = 通常投稿の**8倍以上**
- 大アカウントのリプライ欄上位に入ることで相手フォロワーへのリーチを取得
- `gem_influencer_reply_quote.md` を使って質の高いリプライを効率生成
