# cost-and-delegation.md — コスト管理とタスク委譲のハードルール

APIコストの爆発とコンテキスト肥大を構造的に防ぐための規約。
このファイルは「やらないことの線引き」を定める。**例外なく遵守すること。**

> 重複を避けるため、以下は本ファイルでは扱わない（各既存ルールを参照）:
> - config.py不可侵・APIキー保護 → `security.md`
> - CSV 8列スキーマ死守 → `csv-safety.md`

## 原則 1: 対話型CLIスクリプトを自律実行しない（最優先・コスト爆発防止）

`input()` を伴う対話型CLIスクリプトを、`printf`・パイプ（`echo ... |`）・
ヒアドキュメント（`<<EOF`）などで**強行突破（自律実行）してはならない。**

### 対象スクリプト（例）
- `mini_bulk_generator.py`（件数・カテゴリ・RAG資料の選択を対話で尋ねる）
- その他、起動後にユーザー入力を待つすべてのスクリプト

### なぜ
意図しない選択肢（例: 重いRAG資料の全文読み込み）が自動で選ばれると、
Gemini API への巨大な入力が走り、**1回の操作で数百円〜のコストが発生し得る。**
入力を機械的に流し込むと、この事故を人間が止められない。

### 正しい振る舞い
```
1. 「このタスクは対話型CLIなので、別ターミナルで手動実行してください」と必ず案内する
2. 実行すべきコマンドを提示する（例: venv/Scripts/python mini_bulk_generator.py）
3. Claude自身は実行しない。実行後の出力（ストック件数等）を受け取って後続を支援する
```

緊急でも例外を作らない。「今回だけ自動で」は禁止。

## 原則 2: 重い生成は定額Gemini ULTRAへ委譲する（ゼロイチ生成を抱え込まない）

X記事などの**長文のゼロイチ生成をClaude（あなた）自身で行わないこと。**

### Claudeの役割（この3つに専念する）
1. **構成設計**（タイトル案・小見出し・要旨・根拠の整理）
2. **ハンドオフプロンプトの組み立て**（Gemini ULTRA / NotebookLM に渡す単一ファイル）
3. **生成物の多層レビュー**（機械チェック → QC3基準 → v3トーン → 推敲）

### なぜ
長文生成をClaudeで行うと従量課金が膨らむ。定額プランのGemini ULTRAなら
**生成コストは実質0円。** content-engine原則（書くAIとチェックするAIの分離）の
SOP昇格版。実装フローは `.claude/commands/write-article.md`（Phase3でハンドオフ、
Phase4でレビュー）が司る。x-article SKILL.md の「多層レビュー4層」も参照。

### 例外
- 短文（タイトル15字・ALT100字・リプライ）の生成は対象外（→ `model-routing.md` のFlash経路）
- レビュー・推敲・部分修正はClaudeが行ってよい（生成≠推敲）

## 原則 3: コンテキストを保護する（トークン浪費の抑制）

不要なファイル読み込みでコンテキストを肥大化させない。

### 具体策
- **巨大ファイルの全文Readは避ける** — `自動生成用ナレッジ/*.txt`・トーク履歴・分析CSV等は
  `grep -n`（Grepツール）でキーワード周辺だけを局所的に読む
- **セッションが長引いたら自発的に提案** — 文脈が重い・話題が切り替わったと感じたら
  `/compact`（要約圧縮）や `/clear`（リセット）をユーザーに提案する
- **関係ないアプリのコンテキストを同時ロードしない** — モノレポCLAUDE.md の地図に従い、
  作業対象のcontextファイルのみ参照する（power-diagnoser と auto-poster を混ぜない）

### なぜ
コンテキストが膨らむほど毎ターンの入力トークンが増え、APIコストが線形に上がる。
読まずに済むものを読まないことが、最も確実なコスト削減になる。
