# /project:write-article — X記事（長文記事）作成コマンド

引数のテーマから「お金と法律のお守り」長文版のX記事（2,000〜4,000字）を作る。
本文生成は定額Gemini ULTRAへオフロードし、Claudeは構成設計とレビューに専念する。
必ず先に `.claude/skills/x-article/SKILL.md` を読むこと。

```
使い方: /project:write-article テーマ
例:     /project:write-article 業務委託セラピストの経費、どこまで認められるか
```

## Phase 1: テーマ確認とナレッジ収集

1. 引数のテーマが無い・曖昧な場合はユーザーにヒアリングする（対象読者の悩み・記事を読んだ後にどう感じてほしいか）
2. `自動生成用ナレッジ/*.txt` をテーマのキーワードでgrepし、根拠にできる条文・判例・数字を抽出する
   （ファイルが巨大なため全文Readは禁止。grep -n で該当箇所＋前後を読む）
3. **ナレッジ内に根拠が見つからないテーマは、その旨を報告して中止する**（捏造して書き進めない）

## Phase 2: 構成案の提示（ユーザー承認ゲート）

以下をユーザーに提示し、承認を得てから次へ進む（大枠のズレをここで防ぐ）:

- タイトル3案（誤解フック型を最低1案含める）
- 冒頭フック（1〜2文の方向性）
- 小見出し構成（3〜6個）と各セクションの要旨
- 使用するナレッジの根拠一覧（条文・数字とその出典ファイル）
- 締めの体験質問の案

## Phase 3: ハンドオフプロンプトの組み立て

承認された構成から、Gemini ULTRA用のプロンプトを1ファイルに組み立てて保存する:

- 保存先: `drafts/article_prompts/article_prompt_YYYYMMDD_<テーマ短縮名>.md`
- 構成（上から順に連結）:
  1. `drafts/gemini_gem_prompt_optimized_v3.md` から【3つの顔】【NGトーン・境界線ルール】
     【温度感・口癖】【心理アプローチ絶対ルール】【ペルソナ絶対ルール】【Keita_CPAの声の指紋】
     【会話の実テンポ・相槌・距離感】の各セクションを抽出して転記（v3が単一ソース。要約・改変しない）
  2. x-article SKILL.md の「記事の型」「フォーマットルール」「絶対ルール」
  3. 承認済みの構成案（タイトル・小見出し・要旨）
  4. ナレッジ抜粋（Phase 1で抽出した根拠。これ以外の数字・条文の使用を禁止する旨を明記）
  5. 出力指示: Markdown形式・2,400〜4,800字（推敲で20〜30%削る前提の初稿）・本文のみ出力
- 保存後、ユーザーに「このファイルをGemini ULTRA / NotebookLMに貼り付けて生成し、
  結果を `data/raw_contents/articles/` に .md で保存してください」と案内して一旦終了する

## Phase 4: レビューと最終稿（原稿が用意されたら再実行）

`data/raw_contents/articles/` に未処理の原稿がある場合はこのPhaseから始める:

1. **機械チェック**（SKILL.mdの多層レビュー層②）: 文字数・NGワード（魔法/奇跡/賜物/一体感/完璧/極上/プロ 等）・
   絵文字混入・「。笑」表記・見出し間隔・1段落の行数
2. **品質審査**（層③）: QC3基準（法令のこじつけ／暴言・説教／ナレッジ外数字の捏造）＋
   v3トーン（評論家調・媚び・守秘・読後感が上向きか）＋ 個別税務判断の混入チェック
3. **推敲**: 全体を20〜30%削る。「とても」「本当に」等の冗長語を削除。段落構造をスキミング向けに整える
4. 最終稿を `drafts/articles/article_YYYYMMDD_<テーマ短縮名>.md` に保存し、修正点の要約を報告する

## Phase 4.5: 付随アセットの同時生成（新設・2026-07-08）

記事本体とあわせて、公開に必要な3点セットをこのタイミングで生成する。
予告ポスト・抜粋ポストは通常投稿と同じ短文（280字以内）なので、Gemini ULTRAに委譲せず
**Claudeがここで直接起案する**（cost-and-delegation.md 原則2の短文除外規定に該当）。

1. **予告ポスト案（1〜2案）**: 公開数時間前に投稿する短いティザー。記事の「持ち帰れるもの」を
   明かさず、好奇心と自分ごと感だけで手を止めさせる。persona.md絶対ルール（一人称ぼく・
   絵文字禁止・Markdown太字禁止・URL禁止）に従う。280字以内
2. **抜粋ポスト案**: 公開後に投稿する。記事本文から最も刺さる1段落（フックまたはチェックリストの
   一部）を抜粋し、「続きは記事で」の一文＋`[記事URL]`のプレースホルダーを添える。280字以内
3. **アイキャッチ画像生成プロンプト**: 最終稿のタイトル（H1）とリード文からサブタイトルを抽出し、
   `drafts/gem_eyecatch_generator.md` の入力形式（タイトル1行＋サブタイトル1行）にそのまま
   埋め込んだ状態で出力する。ユーザーはこれをコピーしてアイキャッチ生成Gemに貼るだけでよい
   （ラベル・カテゴリ・改行位置はそのGem側の自動判断に任せる。ここで先回りして決め打ちしない）

出力は最終稿の直後に追記する形で提示する。

## Phase 5: 入稿チェックリストの出力

最終稿・付随アセットとともに以下を出力する（入稿・公開は人間が手動で行う）:

```
[入稿手順] x.com → サイドナビ「記事」→「書く」
- [ ] タイトル・本文を転記し、太字・見出しを書式設定（原稿のMarkdownに対応）
- [ ] Phase 4.5のアイキャッチ画像生成プロンプトをアイキャッチ生成Gemに貼り、画像を生成
- [ ] Phase 4.5の予告ポスト案から1つを選び、公開数時間前に投稿
- [ ] 公開後にプロフィールへピン留め（24〜72時間）
- [ ] Phase 4.5の抜粋ポスト案に記事URLを埋めて投稿
- [ ] 早期リプライへの返信を優先
```

## 注意事項

- X記事の公開はPremium限定機能・**API投稿不可**。システムからの自動投稿は行わない（凍結回避の設計思想とも整合）
- 記事原稿ではMarkdown太字・見出し・箇条書きを使ってよい（通常ポストの禁止ルールとは別。SKILL.md参照）
- 絵文字は記事でも禁止
- 1つでもQC基準に落ちた場合は、該当箇所を修正してから再審査する（落ちたまま最終稿にしない）
