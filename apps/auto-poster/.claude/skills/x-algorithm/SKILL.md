## 3. 単一最大シグナル: Show More（20倍ブースト）

`ControlAiShowMoreScaleFactorParam = 20.0`

「もっと見る」を押させる投稿が**他のすべてのシグナルを圧倒**する。

**設計3原則:**
1. **著者固有情報**: 「Big4でしか見られない」「現場で実際に起きた」など自分だけが知る情報
2. **余韻型終わり**: 「続きは下に→」ではなく、本文が自然に途切れて「え、それで？」と思わせる構成
3. **シリーズ感**: 「【税務調査対策 全7回】第3回:」のような連続性の示唆

## 4. 最大ペナルティ: Show Less（95%削減）

`ControlAiShowLessScaleFactorParam = 0.05`

「Show Less（興味なし）」を押されると**スコアが95%削減**される（FeedbackFatigue 80%削減より重い）。

**【ペナルティA】興味なし（FeedbackFatigueScorer）**
- 80%のスコア削減
- 140日間の長期抑制
- 14日間は完全BAN（FeedbackFatigueFilter）

**【ペナルティB】Show Less（ControlAi）**
- 95%のスコア削減（より深刻）
- 絶対回避: 価値のない投稿・連投疲労・関係ない話題・外部リンク多用

## 5. 初速30分エンゲージメントベロシティ（配信量の最大決定因子）

**投稿後最初の30分間**のエンゲージメント速度が、その後の全配信量を決定する。

**実装への影響:**
- 投稿時刻はセラピストがXを最もよく見る時間帯（朝6-8時・昼12-13時・夜21-23時）に合わせる
- 投稿直後に著者自身がリプライを返すことで初速が上がる
- フックの一文がそのまま「最初の30分でリプライを引き出す」設計になっていること

## 6. TweepCredスコア（隠れた配信制御）

各アカウントは**0-100の隠れたスコア**を持ち、配信量を制御する。

| 閾値 | 配信動作 |
|---|---|
| **65点以上** | 全投稿が配信対象 |
| **65点未満** | 1日3件のみ配信 |

**スコア構成要因:**
- フォロワー/フォロー比（現在 150/13 = 11.5倍 → 良好）
- エンゲージメント品質（高品質アカウントとのインタラクション）
- アカウント年齢（2025年12月開始 → まだ若い）
- Premium加入: **+4〜+16ポイントのブースト**

**スコアアップ施策:**
- フォロワー増加（特に高エンゲージアカウントからのフォロー）
- 低品質フォロワーの整理
- 大アカウントへのリプライでの存在感確立

## 9. Author Diversity Decay（連投ペナルティ）

同一アカウントの投稿がタイムラインに並ぶと減衰:
```
スコア = (1 - 0.25) × 0.5^n + 0.25
```
| 連続位置 | スコア倍率 |
|---|---|
| 0番目（1件目） | 100% |
| 1番目（2件目） | 62.5% |
| 2番目（3件目） | 43.8% |
| 3番目（4件目） | 34.4% |

**対策**: 投稿間隔を最低4〜5時間以上空ける。`conoha_worker.py` のスケジュール設計に反映済み。
