## 1. 設計原理: 教祖ではなく書評

セラピストはXを集客のために使っており、交流や情報収集のためには使っていない。
この前提を変えようとせず、**@Keita_CPA に書かれること自体が集客価値を持つ**構造を作る。

- 紹介長文ポストは、セラピスト本人がプロフィールや固定に置ける「営業資産（推薦状）」である
- 影響力は崇拝（教祖）ではなく選抜から生まれる。「この人に書かれることに価値がある」という状態を作る
- 立ち位置は**書評**: 読んだもの・聴いたものだけで書き、書き手と対象の間に利害も接触もない。
  この中立性こそが、載る人を守り、紹介の価値を担保する
- 紹介文の型（5段構成・営業表現の絶対禁止）は変更しない。広告に見えないからこそ
  営業資産として機能する

制度が機能する3条件:
1. **見えること**: 他の人が紹介されているのが分かる（シリーズ表記＋目次ポスト）
2. **希少であること**: 誰でももらえるものではないと分かる（週1上限・依頼では書かない）
3. **条件が察せられること**: 公開の言葉・声で目に留まった人しか書かれない、と界隈が暗黙に学習する
   （明言したら取引になり壊れる。構造で伝える）

## 2. 最上位ルール: 会った人・施術を受けた人は紹介しない（v2・R1）

**実際に会った人・施術を受けた人は紹介対象にしない。**

- 理由: 特定の客との親密さが公開されることは、セラピスト本人にとってマイナスになり得る
  （他の客の嫉妬・在籍店との関係・イメージ低下）。紹介が「常連客の匂わせ」に見えた瞬間、
  本人の営業の妨げになり、業務妨害のクレーム・トラブルの火種にもなる
- 紹介対象は「**スペース・投稿・リプライ等の公開情報で、いいなと思った人**」のみ
- 生成された紹介文の中でも、対面・施術経験を示唆する表現（「お店で」「施術を受けて」
  「お会いして」等）は禁止（SKILL.md 禁止事項に反映済み）
- 「書かれた人とぼくの間には何もない」ことを目次ポストで公言する（§4）。
  この宣言自体が、載る人への保護として働く
- **紹介した人との関係は公言しない（2026-07-06決定）**: 紹介後にその人と会ったか・
  お店に行ったか・やり取りがあるかを含め、関係について一切公言しない。
  時間差で「あの紹介は常連の匂わせだった」に転化することを防ぐ。X上の公開リプライ等の
  通常の交流は従来どおりでよいが、紹介と対面関係を結びつける発言はしない
- **紹介文の中で自分とのやり取りに触れない（2026-07-06決定）**: 「ぼくのリプライにも
  返してくれる」等の言及は、特別ポジションの主張（SKILL.md NGトーン7）と関係の公言にあたり、
  自慢に転じた瞬間に文章の効力が消える。「交流してくれる人だ」という読者への情報は、
  **第三者への返しぶりの抽象観察**（「リプライ欄での、相手を急かさない返し方」等）で伝える。
  素材収集時、本人から書き手（@Keita_CPA）宛の返信は素材から除外する

## 3. シリーズ設計

### 名称: 「気くばり手帖」（v2で「余韻手帖」から変更・2026-07-06ユーザー承認済み・確定）

- 選定理由: 紹介文の中核＝「見えない気遣いを見抜いて言語化する」（SKILL.md第2段）をそのまま名乗る。
  施術後の「余韻」を連想させない・載る意味が明快・X内でほぼ固有
- 変更箇所は `therapist_introducer.py` の定数 `SERIES_NAME` 1箇所＋本書＋関連ドキュメント
- 候補比較は `docs/introduction_revision_202607.html` §1

### 表記ルール

- 投稿の1行目に「気くばり手帖 その3」（通し番号）、空行を挟んで本文
- シリーズ行は **生成本文に含めない**。`therapist_introducer.py` が採番して自動付与する
  （Gem手動運用時は `data/logs/introductions_log.csv` の最終番号+1 を手で付ける）
- 通し番号は過去実績を遡及編入して数える:
  - その1 = 2026-04-02 @rin_ring_ange
  - その2 = 2026-04-04 @96yuridayo

### 観察素材（v2・R2）

正当な素材は公開情報のみ:
- プロフィール文・通常ポスト・リプライ（従来どおり・スクリプトが自動取得）
- **スペース**（声・話し方・間の取り方。v2で正式素材化）
  - スクリプトはテキストしか取れないため、スペース所感を使う場合は**Gem手動運用**で
    「聴いて観察した事実のメモ」を追加入力する
  - 本人の発言の逐語書き起こしは使わない（リプライの直接引用禁止と同じ理由・監視感の排除）。
    観察の要約（間の取り方・言葉の選び方・温度）のみ

## 4. 掲載場所: 目次ポスト＋自己リプライ方式

プロフィール固定枠は「はじめまして」ポスト（profile_pinned_proposal_202607.md §2）が予約済みのため、
固定枠は使わない。代わりに目次ポストを1本立て、スレッドを台帳にする。

### 目次ポスト本文案 v2（ユーザーが手動投稿）

```
気くばり手帖

タイムラインやスペースで見かけた、忘れがたいセラピストさんを、
長い文章でひとりずつ書き残しています。多くても週にひとりです。

ここに書くのは、会ったこともお店に行ったこともない人だけです。
投稿や声からにじみ出る気くばりだけを頼りに書くので、
書かれた人とぼくの間には、何もありません。

宣伝ではないし、頼まれて書くこともありません。
お店やサービスの話も書きません。書くのは、その人の言葉と気くばりだけです。
一覧はこのポストのリプライ欄にぶら下げていきます。
静かに読んでもらえたら、それで十分です ╰ᘏᗢ ☕︎
```

### 追記運用（紹介ポスト投稿のたびに）

1. 紹介ポストを単独で投稿する（リーチを保つため目次への自己リプライにはしない）
2. 目次ポストに自己リプライで1行追記する:
   `その3 「（紹介文中の言葉から6〜12字の見出し）」 @username さん`
3. 過去分（その1・その2）も同形式で遡及追記する
4. 10件たまったらX記事（長文記事）へのアーカイブ化を検討する（x-article スキル参照）

## 5. 希少性ルール（制度の通貨価値を守る）

1. **週1件を上限とする（木曜夜推奨・2026-07-02確定リズムを維持）**。前倒し・まとめ書き禁止
2. **頼まれても書かない**。依頼に応じた瞬間、書評から御用ライターに転落する。
   依頼が来た場合の返し方（温度の参考・毎回自分の言葉に直す）:
   > ありがとうございます。ただ、あれは頼まれて書くと嘘が混ざる気がして、
   > ぼくが勝手に見て、勝手に書くと決めているんです。
   > だからお約束はできないんですが、そう言ってもらえたのは素直にうれしいです。
3. **対価性ゼロを厳守（ステマ規制ガードレール）**。金銭だけでなく、無料施術・延長サービス・
   優先予約などの便宜も対価にあたる。対価を受けた紹介は景品表示法のステマ規制
   （令和5年10月施行の指定告示）の射程に入り得るうえ、制度の信頼が一度で壊れる
4. **再紹介条件（v2・R3。旧「二重紹介禁止」を置き換え）**: 同一人物の再紹介は次の3条件すべてで可
   - ① 前回の紹介から**3か月以上**経過している
   - ② 前回と重複しない**新素材**がある（例: 前回は投稿ベース、今回はスペースの声）
   - ③ 同一人物への再紹介は**年1回まで**（お気に入り感・選定の公平感を守る）
   - 新しい通し番号を発行し、台帳の波及メモ列に「再紹介・関連ID」を記録する
   - **サブアカウント・別アカウントは同一人物として扱う**（台帳の波及メモで関連IDを管理）
   - スクリプトでは `--reintroduce` フラグで実行する（履歴ブロックを外しつつ台帳に記録される）

## 6. 選定フロー

毎週の選定は次の4条件をすべて満たす人から:

1. **会ったことも施術を受けたこともない**（§2の最上位ルール）
2. `data/config/target_accounts.txt` に載っている（セラピスト個人・フォロワー5,000未満）
3. スペース・投稿・リプライの公開情報で「いいな」と思った実感がある
4. 観察素材が足りている: 公開情報から、5段構成の6:4比率（具体的事実6割）を
   捏造なしで書けるだけの具体的な言葉・エピソードが拾える

### 投稿前グレーチェック（2026-07-06新設・除外基準方式・所要5分）

公認会計士の実名アカウントによる公開の紹介である以上、「個人を紹介しているだけで
店は紹介していない」という区別を受け手はしてくれない。**調査して保証するのではなく、
明白な地雷だけ踏まない**ためのネガティブチェックを、生成前（遅くとも投稿前）に必ず行う:

1. 本人の投稿・プロフィール・リンク先（lit.link等）に明白な性的サービスの示唆がないか
2. 在籍店の掲載ページのメニュー・文言に健全店の範囲を超える（おそれのある）表記がないか
   （例: 内容非公開のリピーター限定コース・段階的に開放される非公開コース等はグレー表記として扱う）
3. 店舗名・本人名で軽く検索し、摘発報道・重大な悪評が出ていないか
4. 年齢に関する疑義がないか
5. **ひとつでも引っかかったら紹介しない**。判断が割れる場合は保守側（見送り）に倒し、
   最終判断は運用者（公認会計士本人）が行う。**交流は通常どおり続けてよい**
   （紹介だけが資格者名義の資産であり、リプライは通常の社交だから）

チェック結果は台帳の波及メモ列に記録する（実施日・判定・根拠）。

補足:
- X上の交流（リプライ往復）実績は素材を厚くするので望ましいが、v2では必須条件ではなく
  「素材が足りるか」で判断する（スペースだけで素材が足りるなら可）
- 投稿前チェック: 特定リスク（店舗名・出勤情報・地域が推定できる記述）を含めない
- 選外への配慮: 「選ばれなかった人」という概念を作らない。順序は「目に留まった順・素材が
  溜まった順」という時間の構造として運用し、優劣の説明を一切しない

## 7. 波及ループ（紹介を次の接点に変える）

投稿後の行動（優先順）:

1. 本人の反応（いいね・リポスト・引用・返信）への返信し返しを最優先で行う
2. 紹介ポストに反応した**同業のセラピスト個人**（フォロワー20〜5,000）を確認し、
   `target_accounts.txt` への追加候補にする（業者・店舗公式は除外）
3. `introductions_log.csv` にポストURLと反応を記録する（§8）

循環: 「紹介 → 本人がリポスト → 同業に露出 → 新しい接点 → 観察 → 次の紹介候補」。
紹介制度そのものが新規セラピストとの接点開拓エンジンを兼ねる。

## 8. 計測（introductions_log.csv・8列）

| 列 | 記入タイミング | 内容 |
|---|---|---|
| Date | 生成時（自動） | 生成日時 |
| Target_ID | 生成時（自動） | 対象アカウント（@なし） |
| シリーズ番号 | 生成時（自動） | 通し番号 |
| ポストURL | 投稿直後（手動） | 紹介ポストのURL |
| 本人反応 | 投稿から1週間後 | like / repost / quote / reply の組合せ（例: repost+reply） |
| 資産採用 | 気づいたとき | 本人が固定・プロフ・ハイライトに使ったか |
| 紹介後の変化 | 翌月の月次分析時 | 本人からの自発的な絡みの変化（例: 自発リプ2件/月→5件/月） |
| 波及メモ | 随時 | 反応した同業・target_accounts追加・依頼の打診・**再紹介の関連ID** など |

月次（/project:monthly-analytics）で見る指標:
- 本人反応率（repost以上 ÷ 紹介数）
- 資産採用数（固定・プロフに使われた件数。制度の集客価値の直接証拠）
- 波及接点数（紹介経由で target_accounts に増えたセラピスト数）
- North Star接続: 紹介済みの相手からのDM・パーソナルな相談の発生

見直し基準: その12（開始から約3か月）まで運用した時点でレビューする。
本人のrepost率が5割を切っている場合は、紹介文の型ではなくまず選定（素材の深さ）を疑う。
